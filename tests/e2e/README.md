# Assembled Browser workflow

`pnpm test:e2e:browser -- --dsh <checkout> --scratch-root <absolute-E-drive-path>` is the single local and CI entry for the packed Agent Organization Browser scenario. `DSH_SOURCE=<checkout>` and `DSH_AGENT_GROUP_SCRATCH_ROOT=<absolute-path>` supply the same values through the environment. The checkout must be the supported DeepSeek Harness commit `639ed015397290b3745d163aafe02ffee4aa3f84` (`0.2.0-rc.2`).

Use Node.js 24 and pnpm 11.7.0, then install repository dependencies and Chromium with `pnpm install --frozen-lockfile` and `pnpm exec playwright install chromium`. The command rebuilds, tests, and packs all three local packages before installing only those tarballs into a clean temporary Web profile. It uses a deterministic local scripted provider and makes no model or credential-bearing network request.

Evidence is written below the selected scratch root in a unique `evidence/packed-<version>-<timestamp>-<run-id>/` directory. A failure retains its isolated scratch path plus the Browser screenshot, ARIA snapshot, redacted console output, Host lifecycle and logs, durable workspace snapshot, installed profile, and cleanup error when cleanup itself fails. Inspect `scratch-path.txt` before cleanup, confirm the resolved path is the owned `dsh-agent-group-packed-*` temporary directory printed by that run, and remove only that exact directory with the native shell after all recorded PIDs have exited. Success removes the scratch profile after every owned browser, context, server, stream, and child process has settled.

Phase-prefixed `direct-rpc-responses.json` independently records Direct HTTP RPC failures even when HTTP status is 200, using only allowed request, correlation and error fields; it excludes URLs, authentication tokens, headers and complete response snapshots.

The development scenario exercises draft editing and explicit assignee confirmation, full-brief Session input, exact-result artifact registration and human review, explicitly confirmed rework, and selected-only artifact handoff. Task-template revisions remain immutable; company-template preview and explicit new-events confirmation do not create tasks, grants or Sessions. A real employee proposal-tool call creates only a draft awaiting human confirmation.

It also creates and renames an independent organization, archives the source, exports portable format 3, previews and confirms import under a new identity, then reopens the restored organization. Checks include workflow history, confirmed briefs, template revisions, exact artifacts/reviews/handoffs and operation receipts, alongside personal memory. Import excludes local Session bindings and source creation metadata, rebases task message identities and does not start employees; the newly committed local organization records its own import creation receipt. New work acquires an independent Session; Host restart preserves the restored organization and its workflow, while the source remains unchanged. These development controls are not included in the published `0.4.0` package.

Restart preserves every existing Session header and row, plus every complete organization record and employee Session binding. The pinned DSH Web workspace restoration may initialize one new core-workspace blank Session on page load. The smoke admits only that exact unseeded standard Session with the profile's three initial permission, sandbox and approval events; another workspace, employee binding, changed old row or any user/model/turn/tool/task event fails the check. Import itself still requires all Session logs to remain exactly unchanged.

The initial organization snapshot waits for both the enabled navigation and a loaded, selected organization directory. A visible loading dialog alone is not ready; an alert or readiness timeout fails instead of accepting an incomplete snapshot.

Release verification runs this command twice consecutively from clean scratch roots. Both runs must pass without retry and must leave two different run directories, each with its own `release-smoke-receipt.json`, phase-prefixed Browser evidence, `host-lifecycle.json`, and logs. Record both printed evidence paths and compare their receipts; do not copy the second run over the first. Observable Browser state, Host readiness, explicit provider gates, and durable records are the deterministic gates; fixed ports and timing sleeps are not acceptance signals.

`--skip-dsh-prepare` is only valid when the exact pinned DSH checkout already has a successful frozen-lockfile install plus fresh `build:lib` and `build:web` outputs produced after its current HEAD and lockfile. Normal local and CI verification omits this flag so the command proves those prerequisites itself.
