# dsh-agent-group v0.1.1

`0.1.1` is the stabilization release for the existing Agent Workspace model. It preserves the version-`0` durable format while tightening validation, error handling, localized presentation, turn convergence, and release evidence.

## User-visible changes

- Every group join requires an explicit choice between memory from new events after the join and an inclusive historical event range.
- Active silent members acquire room-event memory without being woken; only `@agent` and group `@all` route work.
- Direct-message lowercase `@all` is rejected without persisting a room event, while `@alloy` and `@All` remain ordinary text.
- Simplified Chinese and English dictionaries own all plugin labels, status text, accessibility text, empty states, and known policy errors.
- Aborted employee turns do not create durable replies, and reconnect or repeated terminal delivery cannot duplicate a settled reply.

## Data and compatibility

The `agent_workspace` storage-domain version remains `0`. Strict parsing and relationship invariants now run before every durable write. The release loads a captured `0.1.0` aggregate, performs a mutation, restarts, and preserves its identifiers, event order, memory, employment periods, and session bindings.

DeepSeek Harness compatibility is `>=0.1.1-rc.2 <0.1.2-0`. Registry development and release validation use `0.1.1-rc.2`; the verified source point is commit `b150a551b8d465e31e418e1b2eaf5e79bbb7d28e`.

## Release evidence

The candidate was built and tested on Windows with Node.js `24.14.0` and pnpm `11.7.0`. The release gate passed 23 Vitest files with 222 tests and produced the three `0.1.1` tarballs. The isolated source-compatibility command also passed install, build, typecheck, and the same test suite against the declared DSH source commit.

The packed Browser smoke installed only those tarballs into a fresh DSH Web profile and verified definition, agent, group, both join-memory choices, silent-member memory, named mention, `@all`, direct chat, reload convergence, departure, re-employment, and unified personal memory. It then removed the bundle, restarted the same profile, verified that plugin UI was absent, and reopened a core DSH conversation created before installation. The successful receipt binds the source inputs, Browser smoke driver and fixtures, all three tarball hashes, and the DSH version and commit.

Run the candidate gates with:

```sh
pnpm verify:compatibility
pnpm release:pack
pnpm smoke:packed -- --dsh <absolute-path-to-deepseek-harness-0.1.1-rc.2>
```

## Publication checkpoint

This repository state does not itself publish packages, move tags, or create a GitHub Release. After all three packages are published at exactly `0.1.1`, run:

```sh
pnpm smoke:registry -- --version 0.1.1 --dsh <absolute-path-to-deepseek-harness-0.1.1-rc.2>
```

The tag and GitHub Release may be created only after that exact-version registry smoke passes. A failed immutable registry release is corrected with a new patch version.

## Deferred work

Browser task management, memory inspection and retention controls, expanded lifecycle and runtime cancellation controls, multi-workspace support, import/export, and extension UI remain planned for later releases. The existing Host task, delegation, employment, and child-run records remain available. Per-agent model, tool, and skill selection also remains out of scope; top-level agents continue to share the deployment capabilities.
