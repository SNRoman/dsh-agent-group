# v0.5.0

`dsh-agent-group`、`@dsh-agent-group/host` 和 `@dsh-agent-group/web` 统一使用 `0.5.0`。本版将多组织、备份恢复、聊天交办、撤回与场景记忆纳入当前产品，DeepSeek Harness 兼容范围仍为 `>=0.2.0-rc.2 <0.2.1-0`，验证基点为 `0.2.0-rc.2`（`639ed015397290b3745d163aafe02ffee4aa3f84`）。DSH `0.1.1` 部署继续使用插件 `0.2.x`，DSH `0.1.7` 部署使用 `0.3.x`；插件 `0.4.x` 与 `0.5.x` 使用同一 DSH `0.2.0` 兼容范围。

## 主要变化

- 多组织独立保存同事、群聊、任务、记忆和 DSH Session。可以创建、改名、切换、归档及重新开放组织；归档明确选择停止当前工作或等待其完成。
- 浏览器提供备份预览与恢复。当前导出格式为 4，导入接受格式 1–4；确认恢复后创建新组织，不覆盖原组织，也不自动执行历史任务。格式 4 包含工作流、撤回、上下文代次及待处理或失败的重建状态。
- 工作从聊天发起：选择同事并发送完整交办，真实人类消息与任务说明先持久化再投递。同事建议、交接及修改要求保留为待确认草稿；只有人类确认才启动工作，普通提及不会自动授予委派权限。任务卡可跳回已记录的聊天来源。
- 撤回预览展示受影响同事和工作。已经读取相关内容的同事更换 Session，失效来源退出有效记忆和工作复用；清理未完成时保持阻止状态，并允许使用同一操作重试。
- 文件恢复单独选择且默认关闭。可信原始字节检查点支持恢复已有本地普通文件，并在文本可用时显示修改前后预览。每次撤回只处理本次首次失效输入对应的文件，文件重试独立于记忆重建。
- 移出群成员默认保留个人记忆。可明确选择同时移除该同事从此群获得的记忆及有依赖记录的转述，并重建其 Session；其他同事、群消息、独立授权的任务和子智能体结果保留。重新加入会再次同步完整群历史。
- 每次交互的记忆上下文结合当前组织、群聊或任务、发言者、新获得的原文、适用事实候选和相关历史。默认 v2 按需抽取仅处理实际进入该同事模型请求的个人原文片段；记忆界面展示来源、适用范围、候选状态和处理诊断。
- 自动历史选择和记忆搜索使用本地 MiniSearch，支持中文双字及词项匹配，不新增向量服务或嵌入凭据。场景同时携带当前 UTC 时间、Host 本地 IANA 时区及当时偏移；旧事件仍只使用已记录的顺序，远程浏览器不会替换 Host 时区。
- 群聊支持搜索并批量选择同事，搜索保留选择，部分加入失败后重试剩余人员。四个视图统一组织管理、导航、人物卡和主题样式；聊天支持稳定身份提及、个人资料、消息定位及滚动位置保持。

## 安装与升级

首次安装：

```sh
dsh plugin --profile web add dsh-agent-group@0.5.0
```

从 `0.4.x` 升级前，停止所用 profile，完整备份配置、组织存储和 Session 文件，再更新并启动：

```sh
dsh plugin --profile web update dsh-agent-group@0.5.0
dsh web
```

存储域及业务聚合版本仍为 0；启动会把旧本地聚合及版本 1/2 的组织记录升级为版本 3，补足缺失的工作流和通信元数据，保留已有事件、实体身份及 Session 绑定。旧插件不能读取后继记录或格式 4 备份。降级 npm 包不会撤销数据升级；回滚须使用升级前完整备份，不能把新备份当作旧版恢复文件。

## 隐私与恢复限制

备份包含角色指令、聊天、个人记忆和原始撤回历史，应作为敏感文件保存；校验和只检测损坏，不验证作者身份。备份不包含本地 Session、抽取审计与投影域或文件字节，恢复后检查点标为不可用，不能恢复旧模型上下文或文件检查点。未完成的上下文清理在导入后仍保持阻止状态。

撤回和群记忆移除改变可用上下文，不会物理删除原始组织历史、旧 Session 文件或本地抽取审计。默认 `same-model-on-use` 会向同事所用 provider/model 发送实际暴露的原文并增加有预算限制的辅助请求；设为 `disabled` 可停止新抽取。启动、静默收信及只读记忆查询不会批量抽取休眠历史。事实保留原文依据，但抽取分类和模型回答质量不作保证；个人统一记忆也不提供群间保密隔离。

文件恢复仅支持归属明确、有可信检查点的已有本地普通单链接文件。冲突、链接、provider 路径、缺失备份、新建文件删除及缺失文件重建不自动处理；恢复前保存恢复副本。它不能撤销任意 shell 或网络副作用，也不能原子阻止其他进程同时改写同一打开文件。

## 发布与验证

发布遵循[主 README 的发布流程](../../README.md#release)：先完成 `pnpm release:pack` 和完整 `pnpm smoke:packed`，校验回执绑定的源码、烟测输入、DSH 基点与三个 tarball。随后使用官方 `npm stage publish <已验证的 tarball> --access public --registry=https://registry.npmjs.org/` 暂存，并在 npm 网站按 Host、Web、bundle 顺序人工批准；暂存本身不代表版本已公开。此流程需要 npm CLI `>=11.15.0`，详见 [npm staged publishing](https://docs.npmjs.com/staged-publishing/)。

三个包公开后，验证精确 registry 版本：

```sh
pnpm smoke:registry -- --version 0.5.0 --dsh <absolute-path-to-deepseek-harness-0.2.0-rc.2> --scratch-root E:/003code/deepseek-harness-plugins/.tmp/dsh-agent-group-smoke
```
