# v0.4.0

Version 0.4.0 moves the current package line to DeepSeek Harness `>=0.2.0-rc.2 <0.2.1-0`, verified against source commit `639ed015397290b3745d163aafe02ffee4aa3f84`. Deployments using DSH `0.1.7` remain on plugin `0.3.x`; deployments using DSH `0.1.1` remain on plugin `0.2.x`.

The release preserves the durable Agent Workspace version `0`, the `dsh-agent-workspace` forward-export format version `1`, existing package identities, the Browser factory identity, and the Connection RPC path. Definitions, Tasks, Memory, Runtime, definition revision synchronization, and the read-only `export:forward-v1` command retain their existing behavior. The package still provides no import operation.

The candidate passed `pnpm release:pack`: client-copy validation, Host/Web/bundle builds, typecheck, 41 test files with 784 tests, and all three npm packs completed. The exact DSH `0.2.0-rc.2` source check at `639ed015397290b3745d163aafe02ffee4aa3f84` also built all three packages and passed the same 41 files and 784 tests. No production Host or Browser behavior needed an API adaptation; the Browser release fixture moved to a profile-local scripted provider and learned the DSH 0.2 preview notice. The scripted provider is deterministic and makes no model or credential-bearing network request.

Two consecutive packed Browser runs passed from separate clean scratch profiles. Their evidence directories are `packed-0.4.0-2026-10-08T14-22-25-361Z-e31cbed7` and `packed-0.4.0-2026-10-08T14-24-48-849Z-f91293ec` below the configured `E:/003code/deepseek-harness-plugins/.tmp/dsh-agent-group-smoke-040/evidence` root. Each run covered tarball installation, the Agent Workspace workflow, durable restart, plugin removal, and preservation of the pre-existing core Session.

The separate DSH `0.2.1-alpha.1` canary at `5badb15009ae1756c3afe0ae0cef1faafc290ccc` was rejected by the compatibility gate as designed: expected `0.2.0-rc.2`, actual `0.2.1-alpha.1`. That upstream line removes `@deepseek-ai/dsh-invariants` and several package-local invariant export files. This plugin does not import those exports, but its root development manifest still names the removed package, so a future `0.2.1` plugin line must remove that development dependency and run a fresh source and Browser verification. The `0.4.x` supported range remains unchanged.

Preparing this release candidate does not publish packages, create tags, or create a GitHub Release. Those operations require separate authorization after the candidate evidence is reviewed.
