# dsh-agent-group v0.2.0

`0.2.0` turns the persistent colleague model into a complete work surface. Definitions, Tasks, unified Memory, and Runtime activity now share one durable identity model while keeping live execution state separate from recorded facts.

## Product workflow

- Definitions create reusable roles and immutable revisions. Saving a new definition revision can synchronize no colleagues, all eligible colleagues, or an explicit subset; names, employment periods, rooms, sessions, and Memory remain attached to the same colleagues.
- Tasks provide human assignment, task-scoped delegation grants, derived peer work, durable delivery attempts, retry after failure, cancellation, results, and one-shot child runs. An agent may delegate only under a human grant for that root task.
- Memory unifies room events, selected pre-join history, task results, and child results for each colleague. Silent active group members remember admitted events even when they are not mentioned.
- Runtime shows queued, responding, tool, stopping, and settled activity from the current Host process. Exact stop interrupts one activity; it leaves the task open for retry, records no task result, and does not cancel unrelated queued work.

The established behavior remains fixed: mentioned colleagues must reply; unmentioned colleagues do not speak spontaneously; colleagues may mention one another; a human must explicitly assign formal work; and a colleague may create a one-shot child directly or ask the human first when judgment is required.

## Data and cancellation

The `agent_workspace` storage-domain version remains `0`, and released v0.1.x aggregates load without migration. Every new mutation uses optimistic revision checks and the same aggregate invariant pass. Model-visible task delivery is associated with its durable task, attempt, message, assignee, and captured definition revision.

Root cancellation cascades across open tasks in that root tree and expires its active grants. Cancelling a derived task affects only that task. Durable cancellation wins before runtime cleanup; late output is retained only as interrupted Session evidence and never becomes a task result.

## Forward compatibility export

v0.2.0 freezes `dsh-agent-workspace` format version `1` as the producer used by the future v0.3 compatibility matrix:

```sh
pnpm build:host
pnpm export:forward-v1 -- --input E:/exports/agent-workspace.json --output E:/exports/workspace-portable-v1.json --exported-at 2026-09-04T00:00:00.000Z
```

The command accepts exactly one version-0 local aggregate, validates its relationships, preserves portable definitions, colleagues, lifecycle, rooms, Tasks, Memory, events, and child results, and omits local session bindings. It writes an RFC 8785 canonical document with a SHA-256 digest, refuses to overwrite an existing destination, and does not modify the input. This release deliberately provides no import endpoint and no Browser export/import UI.

## Compatibility and release evidence

DeepSeek Harness compatibility remains `>=0.1.1-rc.2 <0.1.2-0`. Registry development and release validation use `0.1.1-rc.2`; the verified source point is commit `b150a551b8d465e31e418e1b2eaf5e79bbb7d28e`.

The pre-publish gate builds and tests all packages, packs exact `0.2.0` tarballs, installs them into a clean DSH Web profile, calls the installed Host exporter against the captured v0.1 aggregate, and drives the full four-view Browser workflow. It verifies group memory policy, exact mention cardinality, human grants and derived Tasks, child tool/result causality, denial safety, Memory filters and provenance, selective definition revision synchronization, exact Runtime stop, Host restart convergence, uninstall, and preservation of a core DSH conversation.

Run the candidate gates with:

```sh
pnpm verify:compatibility
pnpm verify:client-copy
pnpm build
pnpm typecheck
pnpm test
pnpm test:e2e:browser -- --dsh <absolute-path-to-deepseek-harness-0.1.1-rc.2>
```

## Publication checkpoint

This candidate does not publish packages, create tags, or create a GitHub Release. Those operations require separate authorization. After all three exact `0.2.0` packages are intentionally published, verify the immutable registry artifacts with:

```sh
pnpm smoke:registry -- --version 0.2.0 --dsh <absolute-path-to-deepseek-harness-0.1.1-rc.2>
```

Do not create or move a tag before that exact-version registry smoke passes. A failed immutable registry release is corrected with a new patch version.

## Deliberate limits

The product still uses one local workspace, all top-level colleagues share deployment model/tools/skills/permissions, unified Memory is not a hard secrecy boundary, and child agents remain one-shot. Portable import, multi-workspace discovery, and per-colleague capability selection remain future work.
