# Agent Workspace v0.3.0 Compatibility Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Every behavior change also uses superpowers:test-driven-development: add the focused test, observe the intended RED failure, implement the minimum GREEN behavior, and refactor only while green. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver isolated multi-workspace lifecycle management, recoverable canonical backups, an evidence-backed DSH compatibility matrix, and narrow versioned Host/Web extension APIs without changing the established agent behavior model.

**Architecture:** Keep one atomic storage-domain record per workspace and derive the directory by enumerating those records. Add an application-level record version and deterministic legacy migration, place every employee/queue/turn/child resource inside a workspace runtime capsule, and carry `workspaceId` through all Host and Browser operations. Build backup and extension capabilities on immutable projections and schema-validated append-only events; neither surface receives the mutable aggregate or installation-local session bindings.

**Tech Stack:** TypeScript strict ESM, React 18, Cordis, DSH `0.1.1-rc.2` and `0.1.2-rc.1`, Zod 4, `canonicalize` 2.1, Node crypto SHA-256, Vitest, pnpm 11.7.0, Playwright, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-02-v0.3.0-compatibility-foundation-design.md`

## Global Constraints

- Start only after the `0.2.0` product-closure branch is green and its task, unified-memory, runtime-status, stop, revision-history, stale-revision, and Browser projections are present.
- Before publishing `0.2.0`, ship its read-only `createForwardWorkspaceExportV1` helper and generate the exact `0.2.0` forward-export fixture required by Task 12; `0.3.0` must prove a real previous-version producer rather than synthesize its own predecessor evidence.
- Registry-produced `0.1.1` and `0.2.0` fixtures are post-publication evidence. Before explicit publication authorization, use clearly labeled packed-candidate provisional fixtures for implementation and migration tests; replace them only with untouched exact-registry outputs after publication.
- Keep the DSH `agent_workspace` storage-domain version at `0`; use `WORKSPACE_RECORD_VERSION = 1` for the application record.
- Preserve `local` as the migrated legacy workspace id; never infer `local` for a request that omitted `workspaceId`.
- Labels are non-unique display values. Workspace, operation, entity, event, cursor, and extension ids remain opaque at package boundaries.
- Every Host snapshot, mutation, stream, runtime item, memory cursor, task delivery, export, and extension invocation is scoped by `WorkspaceId`.
- Archive admission and mutation use the same per-workspace serialization lane; the committed `archived` descriptor rejects every later admission before queue or session mutation.
- Export/import never carries DSH session ids, credentials, configuration, environment variables, Host filesystem paths, live handles, transient streams, or Browser state.
- Export format `dsh-agent-workspace`, format version `1`, uses RFC 8785 canonical UTF-8 bytes and SHA-256; the integrity value detects corruption and is never described as trust or authenticity.
- Export documents declare compatible import range `>=0.3.0 <0.4.0`; producer version/range remain diagnostics and never override candidate validation.
- Import mode is create-new only. It never overwrites, merges, or deletes an existing workspace.
- Host import limits are configurable with defaults: `maxDocumentBytes = 16_777_216`, `maxAggregateRecords = 50_000`, `maxEvents = 100_000`, `maxStringBytes = 1_048_576`, and `maxExtensionPayloadDepth = 16`.
- The published DSH peer range is `>=0.1.1-rc.2 <0.1.2-0 || >=0.1.2-rc.1 <0.1.3-0`; required release points are commits `b150a551b8d465e31e418e1b2eaf5e79bbb7d28e` and `a66e4702047846cdaa10c66c9d3df3951f5ea70d`.
- Required Node points are exactly `22.19.0` and `24.0.0`; pnpm is exactly `11.7.0`. DSH `main` is an allowed-failure source canary and never changes manifests.
- Canary output is diagnostic only: it cannot satisfy a required release-point result, widen the supported range, mutate compatibility metadata, or block a release whose declared required points pass.
- Host extension API major is `1`. Registration ids use `reverse.domain/name`; duplicate ids and ranges not containing major `1` fail during plugin load.
- Extension persistence uses only core event discriminator `extension/event`; an absent extension cannot make its historical event unreadable.
- Browser extensions are additive within Agent Workspace-owned contribution regions and cannot replace Conversations, Colleagues, Tasks, or Memory.
- Existing equal-rights, mention, human-root-delegation, child, unified-memory, employment, and definition-revision rules remain unchanged.
- Every plugin-owned visible string remains in the typed `agentWorkspace` locale dictionaries. Imported labels and workspace event content are user data and are not translated.
- No production behavior is added before its focused test fails for the intended missing behavior.
- Do not push, publish, move tags, or create a GitHub Release without the product owner's explicit instruction.
