# Agent Workspace v0.4.0 适配 DSH 0.2 实施计划

> **供智能体执行者使用：** 必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans`，逐任务执行本计划。所有步骤使用复选框追踪。

**目标：** 产出一个保持 `0.3.0` 产品与数据语义、可在 DSH `0.2.0-rc.2` 安装和运行的本地 `0.4.0` 候选版本。

**架构：** 兼容声明继续作为版本、依赖范围、源码验证点和文档的唯一来源。先更新发布元数据并锁定精确 DSH 源码，再以编译失败和行为回归测试驱动 Host、Browser 与测试夹具的最小适配，最后用三个打包产物执行两轮干净配置浏览器验收。DSH `0.2.1-alpha.1` 只做只读探测，不进入 `0.4.0` 支持范围。

**技术栈：** TypeScript 6、Node.js 24、pnpm 11、Vitest、Playwright、Cordis、DeepSeek Harness 插件系统。

**规格：** `docs/superpowers/specs/2026-10-08-dsh-0.2-compat-design.md`

## 全局约束

- 插件版本为 `0.4.0`；支持范围为 `>=0.2.0-rc.2 <0.2.1-0`。
- 精确验证点为 DSH `0.2.0-rc.2`、提交 `639ed015397290b3745d163aafe02ffee4aa3f84`。
- `0.2.x` 与 `0.3.x` 插件兼容线保持不变，一个包不跨 DSH 客户端架构。
- storage-domain 版本仍为 `0`；工作区记录、标识、事件顺序、会话绑定和 forward export v1 不迁移、不重写。
- 智能体权利、提及响应、显式人类委派、子智能体和统一个人记忆语义保持不变。
- DSH `0.2.1-alpha.1` 仅为 canary，不进入 peer range 或发布声明。
- 测试临时目录显式放在 E 盘；成功后删除所属 scratch，失败时保留诊断证据。
- 本计划不授权 push、merge、tag、GitHub Release 或 npm 发布。

## 最终审查重点

- 已归档员工会话在恢复、空闲等待或再次归档失败时，必须销毁未发布 handle 并恢复隐藏状态；Task 3 增加失败路径测试。
- 插件卸载或热重载后 `/agent-workspace` 路由必须被注销并能再次注册；Task 3 保留并重跑卸载重装测试。
- DSH `0.2.0-rc.2` 的插件兼容检查必须在无 exemption 时接受三个 `0.4.0` 包；Task 2 与 Task 4 分别覆盖清单和真实安装。
- DSH Session 投影变化不能让任务因读取过时的同步历史而丢失工具结果或结束原因；Task 3 为实际适配到的新读取方式增加行为测试。
- Browser 外部模块表变化不能在页面打开后才暴露缺失模块；Task 3 进行构建产物静态检查，Task 4 用真实页面验证。
