# Agent Workspace v0.1.1 Stability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Every behavior change follows superpowers:test-driven-development: add one focused test, observe its expected RED failure, implement the minimum GREEN change, then refactor while green. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release `dsh-agent-group@0.1.1` from a reproducible registry-based development baseline, with strict durable validation, stable localized errors/copy, correct direct-room and aborted-turn behavior, and clean-profile packed/public installation evidence.

**Architecture:** Keep the released one-record `agent_workspace` format and additive Browser overlay. Move contributor dependencies to the verified npm DSH release, use a machine-readable compatibility declaration plus an isolated opt-in source check, validate every candidate aggregate before its one-record commit, and keep transient turn convergence separate from durable room facts. Release verification has a pre-publish tarball path and a post-publish exact-registry path.

**Tech Stack:** TypeScript strict ESM, React 18, Cordis, DSH `0.1.1-rc.2` public packages, Zod 4, Vitest, pnpm 11.7, GitHub Actions, Playwright/browser accessibility snapshots.

**Spec:** `docs/superpowers/specs/2026-09-02-v0.1.1-stability-design.md`

## Global Constraints

- Work on `codex/v0.1.1-stabilization`, which started from `origin/main`; do not modify the user's other branches or tags.
- Keep `agent_workspace` storage-domain version `0` and the released durable fields unchanged.
- Default install/build/test must not require or resolve through `../../deepseek-harness`.
- Published packages keep DSH range `>=0.1.1-rc.2 <0.1.2-0`; the development lock pins verified registry artifacts.
- The only source-compatibility target in this release is the finite point declared in `compatibility.json`; an adjacent mutable DSH branch is never implicit.
- Browser integration remains additive and owns no core DSH `sidebar`, `conversation`, or `details` slot.
- Every plugin-owned visible string uses the `agentWorkspace` locale namespace; user/model/tool data is never translated.
- Direct-room lowercase token `@all` is rejected before mutation; group `@all` behavior is unchanged.
- A successful employee turn produces at most one durable room reply; an aborted employee turn produces none.
- No production behavior is added before its focused test has failed for the intended missing behavior.
