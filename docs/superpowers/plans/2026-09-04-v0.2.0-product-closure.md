# Agent Workspace v0.2.0 Product Closure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Every behavior change follows superpowers:test-driven-development: add the focused test, observe the intended RED failure, implement the minimum GREEN change, then refactor while green. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `dsh-agent-group@0.2.0` with a complete Browser workflow for formal delegated tasks, unified personal memory, exact runtime control, and immutable definition revision synchronization, while preserving every `0.1.x` durable aggregate.

**Architecture:** Keep `WorkspaceState` as the only durable aggregate and storage-domain version `0`. Add canonical task-delivery and cancellation events, then assemble task, memory, definition-history, and runtime projections from that aggregate plus DSH's durable inbox/session records. Browser mutations call explicit plugin-owned RPC endpoints with compare-and-swap revisions; agent mutations use model-facing tools whose actor is derived from the executing DSH `Agent`. Ephemeral activity and controller registries never enter `WorkspaceState`.

**Tech Stack:** TypeScript strict ESM, React 18, Cordis, DSH `0.1.1-rc.2` public packages, Zod 4, Vitest, pnpm 11.7, Playwright, DSH JSON storage, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-02-v0.2.0-product-closure-design.md`

## Global Constraints

- Start from the completed `v0.1.1` release branch after its release commit is present; keep unrelated worktree changes intact and do not retarget tags in implementation commits.
- Keep the `agent_workspace` storage-domain version at `0`; do not add a migration, a second task store, or durable runtime/UI filter fields.
- Existing `WorkspaceState` record fields remain unchanged. New behavior is represented by closed-union event variants and ephemeral Host projections.
- Preserve all `0.1.x` ids, rooms, memberships, memory entries, session bindings, and event sequences on load.
- Every Browser mutation parses opaque ids into branded ids, supplies `expectedRevision`, compares it inside the serialized `KvTable.update` callback, and returns the committed revision.
- The Host `room/join` RPC continues to require an explicit `memoryStart`; neither Host nor Browser supplies a fallback. The Browser offers only `new-events` or a validated inclusive `event-range` selected by the human.
- Human RPC endpoints always use `WEB_WORKSPACE_HUMAN_ID`; no RPC payload accepts an agent actor id.
- Agent-facing task tools derive the actor from `ToolRunContext.agent` through the plugin-owned employee pool; tool arguments never contain `actorAgentId`.
- Persist a root assignment and `task/delivery-started` before inserting the DSH inbox message. One open task has at most one nonterminal attempt.
- Stop operations target the exact plugin-owned activity/child identity. Top-level cancellation calls `Agent.cancel({ kind: 'user' }, { keepInbox: true })`; it never disposes an employee or cancels by session id alone.
- Personal memory remains append-only and read-only. The first acquisition of an agent/event pair owns displayed provenance; later acquisitions are idempotent.
- New model-visible agent room replies and task results record the active `definitionRevisionId`; historical values are derived deterministically or displayed as unresolved.
- All new visible copy, including accessibility labels and errors, is owned by the typed Simplified Chinese and English `agentWorkspace` dictionaries.
- Every new product-visible Browser path updates the deterministic assembled-profile test. When a pull request is prepared, record the required real-flow GIF only after the implementation is independently reviewed and committed, using the real server and model rather than the scripted CI adapter.
- No product code is written before its focused test fails for the intended missing behavior.
