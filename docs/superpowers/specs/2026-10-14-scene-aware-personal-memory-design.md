# 场景感知的统一个人记忆：设计提案

状态：用户已授权实现，开发进行中；未完成项仍以验收结果为准。本文不改变已安装插件、DSH 配置或用户组织数据；不包含发布或提交授权。

## 概述

每位同事保有自己的经历，换群、私聊和重启后仍能取用；每轮回复依据本轮场景，区分长期约定、临时要求和已结束的工作。新经历不被旧长文挤掉，事实变更能生效，撤回能排除原文及派生内容。保持无 @ 不发言、只有明确交办才开始正式工作的规则。

推荐组合为：DSH 的 Agent、Session、持久化、压缩和上下文扩展能力，插件拥有的个人记忆与场景管理，以及可替换的本地检索后端。第三方组件仅提供提取、索引或检索，不决定谁有资格知道、当前授权或撤回政策。这里的“最优”指兼顾当前产品效果、部署成本、数据控制和可验证性，不宣称已实测出全市场最佳后端。

## 用户看到的效果

“记得”不等于每轮复述全部历史。同事根据当前问题自然使用有关经历，不提无关旧事；个人记忆不变成全组织共享知识。

| 场景 | 目标效果 |
| --- | --- |
| 群1无 @ 说“以后称呼我虞总”，群2问“现在知道了吗” | 获得过消息的同事能使用新称呼，不要求用户补“查记忆”等口令；未获得消息的同事不会装作知道。 |
| 长期偏好中文，当前交办要求客户邮件用英文 | 邮件用英文；随后日常聊天仍用中文，不延续邮件的临时要求。 |
| 项目已经停止，后来问“上次项目怎样了” | 记得项目及当前停止状态，回答问题，不重新执行、交办或 @ 别人继续工作。 |
| 从工作群切到闲聊群 | 保留人物与经历，但按当前话题回应，不默认沿用上一群的汇报格式或项目目标。 |
| 两个历史项目都存在“上次方案” | 指代足够明确时使用相关上下文；仍有实质歧义时简短确认，不猜测。 |
| 称呼 A 改为 B，之后撤回 B | 知道新约定的同事先采用 B；撤回后 B 不再进入有效记忆。是否恢复 A 取决于 A 的来源仍有效、范围适用。 |

普通聊天、正式交办和同事间回应共用记忆机制，但保留各自的行为规则。历史资料只提供依据，不授予执行或委派权限。

## 方案选择与复用

三种可行路线中，推荐第二种。后端选型不阻塞本次已发现的消息漏同步修复。

| 路线 | 适用性与代价 |
| --- | --- |
| DSH 会话历史检索加明确补查规则 | 可用于找回已进入 Session 的记录；仍需要接入无 @ 消息、个人获得关系和重要约定。可作为历史核查能力。 |
| DSH 基础能力加场景化分层个人记忆 | 保留当前同事身份与 Session，统一消息同步、长期约定、检索和撤回；适合本插件，作为默认路线。 |
| 独立记忆服务或完整时序知识图谱 | 更适合大规模关系与时序查询，需要额外服务、配置和治理；保留接入位置，不作为第一版必需部署。 |

DSH 继续负责智能体运行、角色与工具组合、会话记录与恢复、token 测量和会话压缩。插件继续负责组织、同事、群成员关系、事件、工作状态和撤回。统一的记忆入口负责准备本轮上下文、搜索、读取与派生项失效，群回复、正式任务及记忆工具都使用它；不改 DSH agent-loop，不另建智能体框架。

复用评估先覆盖 DSH 生态的原生记忆组件，再对比通用记忆库。候选必须通过中文、个人隔离、来源追踪、更新、撤回和重启测试，才决定接入；不能凭 README 或厂商分数选定。仅按用户/项目共享的组件不能直接给所有同事挂上同一份可读存储。组件不支持来源级失效时，只能提供经过插件过滤的检索结果，不能成为有效记忆的权威。

默认本地保存源事件与派生资料，不注册新云账户、不自动上传历史。抽取与 embedding 的数据去向、提供方和费用由明确配置决定；使用已配置模型不等于允许向任意新服务发送资料。

保持现有模型、工具与技能的平等能力。本方案的个人隔离约束记忆服务及模型输入，不新增操作系统级文件或进程隔离，也不宣称能阻止具有通用文件权限的工具从其他途径读取资料。

## 每轮如何使用记忆

本轮上下文由五类材料组成，分别保留预算和来源，而不是把所有消息放在一个关键词榜单里截取。

| 材料 | 内容与作用 |
| --- | --- |
| 当前场景 | 本轮组织、群/私聊/正式任务、发言人、真实收件人、当前时间、近期相关对话、有效工作状态与授权。决定本轮正在回应什么。 |
| 新获得的经历 | 该同事已经获得、但尚未覆盖到当前上下文代际的有效消息与历史补入。保护新信息不被旧检索结果挤掉。 |
| 核心约定 | 少量稳定且适用的称呼、交流偏好和持续约定。以有来源的资料提供，不依赖每次恰好搜中。 |
| 相关历史 | 通过话题、语义、关键词、人物与时间取回的事件或事实，并保留必要的邻近消息。 |
| 核查入口 | 原文读取、来源、遗漏提示和检索工具；不足时继续查，查询故障不能解释为“从未说过”。 |

### 当前场景逐轮重建

场景来自当次真实投递与权威组织状态，不复用上一轮的群、任务或授权。人类提问、正式工作和同事 @ 回应明确标记；同事转述的人类指令不是新的直接授权。近期上下文以当前群/私聊和正在讨论的主题为主，跨群经历作为有来源的背景补充。

新投递在实际进入同事串行轮次时，从最新有效快照准备场景与记忆增量，并校验上下文代际；排队前的快照不能作为最终输入依据。恢复已经持久化的输入则保留原记录内容及来源，不悄悄改写该输入；撤回仍通过代际屏障阻止旧输入继续执行。

上下文明确区分“这次要答的问题”“该同事已经知道的资料”“过去发生的事情”。历史中的指令、工具输出、引用与推测都作为数据，不升级为系统规则。当前房间成员目录和当前任务状态每轮刷新，避免旧名单、旧目标和已失效权限继续影响行动。

### 新经历优先、按个人获得关系同步

无 @ 仍向有效成员记录记忆获得关系，但不启动同事回复。下一次唤醒时先覆盖尚未同步的新经历；这一步不等待事实抽取或 embedding，也不与旧历史检索共享可被长文耗尽的预算。

同步依据个人获得增量及上下文代际，而非只看事件序号：后加入群可能刚获得很早的事件。记录区分原文覆盖、可追溯摘要覆盖和仍未覆盖的资料；只有实际输入已持久记录后，才能提交相应覆盖凭据。失败、重试、重启、历史补入与 Session 重建不误确认送达。取得摘要不等于读过全部原文，也不删除原事件记忆。

增量超过预算时分批处理，使用带来源的精简表示与待补查入口，不让一个长消息独占全部空间，不把未覆盖资料标成完整覆盖。索引落后时仍可提供新原文；重要约定的形成不依赖索引处理完成。超预算时保留明确遗漏标记，不能暗示模型已经看到全部经历。

### 核心约定保留范围和证据

核心资料按人类身份与同事的实际经历确定，不通过名字相似合并不同人。明确的长期约定可跨群使用；“本群这样称呼”“这份邮件用英文”等群或任务限定单独保存，不扩展为永久个人偏好。临时约定到期或任务结束后，恢复适用的长期偏好；长期称呼不因近期未使用而自动遗忘。

每项派生资料保存来源事件、发言人、适用范围、有效状态、替代关系及抽取版本。人类明确陈述、同事陈述、工具观察和模型推断分别记录；智能体自己的重复回答不能把推断升级为人类确认。抽取一次源事件可以复用计算，但返回给某位同事的事实只能由他已经获得的有效来源支持。

### 历史检索理解本轮话题

查询结合当前问题、当前话题与邻近对话；“现在知道了吗”不能只靠该句话独立分词。剥除内部 @ 编码，不把 agent id 数字、通用代词或无关重复词作为高相关证据。关键词与语义渠道合并候选、去重与重排，并利用人物、任务、时间和有效状态；embedding 是可配置渠道，不是新增消息送达的前提。

检索优先取短的、可独立理解的事件/事实，再按来源补邻近原文；摘要是定位线索，不替代原始证据。候选分配单项上限并控制重复内容。对不同历史问题使用当时的有效值，对“现在怎样”使用当前值；不能把最新值错误套入历史问题。

当前明确要求在其适用范围内决定本轮表现，但不越过系统规则或当前授权。群/任务临时要求在匹配范围内优先于一般偏好；不同事实或不同范围不互相覆盖。当前权威工作状态优先于过时的项目摘要。证据不足先查询，仍有冲突或指代歧义再确认；只有完成有意义的核查后才说明确实不知道。

时间信息来自真实记录，并区分消息发生、个人获得和派生处理时间。没有精确时间的旧事件只使用已知日期或先后顺序，不补造时间，不把抽取或送入模型的时间当成原消息发生时间。

## 更新来源与撤回

所有派生资料都可从有效源事件重建，原事件仍是依据。普通改口保留过去事实与替代关系，回复按本轮范围和时间选值；撤回排除源事件及其受影响的派生结果，两种操作不能混为一谈。

常驻约定、新经历、自动召回、工具搜索预览和原文分页读取均记录实际模型可见文本及展开后的源事件集合。现有输入依赖和上下文代际机制用于追踪受影响输出与工作；记忆工具读取的依赖也纳入同一记录，不能只登记最初自动召回。

撤回先禁止有效读取与旧代际提交，再失效或重建相关事实、摘要、索引及缓存，并重建已经使用过撤回内容的上下文。后台抽取提交前重新检查来源有效性；迟到任务、旧工具结果和恢复缓存不能使内容复活。重建失败保持阻断及明确重试，不用“没搜到”掩盖遗忘失败。原始审计资料保留，与可供模型使用的记忆分开。

第三方查询返回前仍检查组织、同事获得关系和所有支持来源的有效性。同一工作目录下的其他同事 Session 不天然可读；通用 DSH 会话检索需经过个人资格检查，不能用其 cwd 授权替代组织规则。

## 成本失败与可观察性

普通场景构建从真实请求与持久状态获得，不每轮增加一个独立“判断场景”的模型调用。相同源事件的抽取和 embedding 按内容、版本去重复用，后台有界批处理；常驻资料精简，长原文按需读取。模型输入材料按用途分别配置预算，并受模型真实上下文余量约束；当前人类指令和有效授权不被静默截断。

索引、抽取、embedding 和重排都有处理进度与明确可用状态。未配置可选渠道时使用已声明的基础能力；配置错误及时报错，运行时渠道失败明确报告降级或不可用，不装作完成过不存在的语义检索。新经历送达不依赖这些渠道；必要资料无法安全准备时，应暂停相应回复并提示重试，不使用过期敏感内容。

个人记忆详情能够解释一项资料来自哪个群、哪条消息、何时更新、当前是否适用。本轮调试记录能够说明使用了哪些记忆、哪些因范围/失效/预算未采用；这些诊断默认折叠，不占日常聊天空间，也不在跨组织页面暴露隐藏来源。

## 实施顺序与验收

以下为计划中的交付顺序和验收，不代表测试已执行。每阶段有独立效果检查，后端调研不代替产品行为验收。

1. 场景与送达：统一输入准备入口，逐轮场景、个人新增同步、分区预算、来源日志和记忆工具依赖接入现有撤回机制；先复现并消除本次跨群称呼遗漏。
2. 约定与更新：源驱动核心资料、人物/群/任务范围、可信程度、时效与替代关系、迟到抽取拒绝及派生失效。以称呼、语言、项目停止、改口和撤回验证。
3. 检索与效果：在相同中文历史与产品场景下比较 DSH/生态候选与基础检索，验证混合检索、指代、长历史和成本；选择通过个人隔离与撤回测试的可维护组件，记录实际能力，固定版本后接入。没有合格组件时报告具体缺口，不凭宣传宣布选型成功。

| 验收项 | 通过依据 |
| --- | --- |
| 无 @ 的跨群新约定 | 旧长文占据检索候选、抽取延迟时，新称呼仍实际进入两位有资格同事的下一轮模型输入，真实回复使用它。 |
| 场景切换 | 英文邮件按当前任务要求生成，随后中文闲聊不延续该任务的临时要求或汇报格式。 |
| 旧任务停止 | 能回答历史与停止状态，没有新任务、重试、委派或后台执行。 |
| 范围与身份 | 同名同事、同名人类、不同组织、没获得来源的成员均不会串记忆；后加入取得旧历史的成员可用相应资料。 |
| 改口与历史问题 | 当前问题用适用的新值，历史问题可答旧值；群限定的新值不污染其他群。 |
| 撤回与竞态 | 原文、核心资料、摘要、搜索、工具读取、缓存和重启后均不再返回失效内容；迟到抽取和旧代际输出被拒绝。 |
| 多源派生项 | 不可见来源不混入摘要；撤回一项支持来源后，该派生项重新验证或重建，不沿用过期结论。 |
| 模糊提问 | 邻近上下文足够时正确关联；两个合理项目均可指代时简短确认，而不是自选一个。 |
| 可追溯与恢复 | 所有实际模型输入都能从日志重建并找到来源；重启与代际更新不遗漏获得增量，不误确认完整覆盖。 |
| 成本与检索故障 | 同一语料记录输入 token、额外调用、延迟和命中/回答效果；预算生效，故障可解释，不能返回虚假的“从未告诉过我”。 |

确定性测试首先检查信息送达、权限、范围、失效与恢复；实际模型验收检查最终回答，不以“表里有记忆”代替“本轮能取用”。长历史评测借鉴 LongMemEval 的跨会话、时间推理、更新与未知信息克制维度，再加本插件特有的成员资格、无 @、任务授权和撤回场景。

## 依据与限制

复用基础已经存在：[同事的 Session 创建与恢复](../../../packages/host/src/runtime.ts)、[模型输入准备与代际](../../../packages/host/src/workspace-runtime.ts)、[个人获得关系投影](../../../packages/host/src/memory-query.ts)、[输入依赖记录](../../../packages/host/src/communication-contract.ts)、[有效事件与级联失效](../../../packages/host/src/communication.ts)、[撤回重建](../../../packages/host/src/message-recall.ts)。本方案尚未增加这些模块的任何实现。

可参考 [DSH 第三方记忆接入说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/mcp-memory.zh.md)、[dsh-auto-memory](https://github.com/AskTheWay/dsh-auto-memory)、[dsh-living-memory](https://github.com/dearbld/dsh-living-memory)、[Letta 核心记忆](https://docs.letta.com/v1-sdk/memory/memory-blocks)、[Mem0 当前算法说明](https://docs.mem0.ai/migration/oss-v2-to-v3)、[Graphiti](https://github.com/getzep/graphiti) 和 [LongMemEval](https://arxiv.org/abs/2410.10813)。候选组件的功能以其文档与源码为评估起点，尚未在本插件中验证兼容性或质量，不把第三方自报成绩当作我们的验收结果。

本方案不承诺全部历史原文每轮常驻，也不能保证任意模型从不出错。原文保留、可靠同步、明确适用范围、来源核查和实际回答评测共同降低错误。不得通过无限增加上下文、组织全知或任意把聊天内容升为系统指令来达到表面的“记得”。
