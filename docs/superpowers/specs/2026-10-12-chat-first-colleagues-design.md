# 聊天驱动的同事、工作卡与撤回遗忘

状态：需求方向已确认，本文等待用户审核；尚未进入本轮产品实现。

## 1. 产品目标

用户通过聊天与具名同事沟通、交办工作，再查看某位同事做过的工作与拥有的记忆。岗位定义、修订、授权、执行尝试与事件记录支持这些交互，不作为日常操作的主要对象。

用户已确认：任务只能通过聊天消息产生，工作页用于按同事查看任务卡，每张卡能查看来源；撤回必须让已经读过消息的同事不再从本插件的记忆或旧会话中取得该内容。上一轮样式调整保留，本轮同时解决此前反馈的九项问题。

保持原有规则：被 @ 的同事必须有可见回应，未被 @ 不主动发言；可以主动 @ 其他同事，但沟通不等于工作分配授权；人类显式委派后才能给其他同事分配任务；已授权工作内的一次性子智能体沿用现有规则。同事仍只有在职、离职两种任职状态，使用统一的个人记忆；每次加入群聊仍由用户选择记忆起点。

## 2. 聊天

主导航为“聊天 / 同事 / 工作 / 记忆”。群聊名称可以从聊天标题的管理入口修改，保存后更新列表、来源标签与后续显示，群聊身份、成员和历史不变。私聊以对方同事命名，不伪造第二个可独立修改的同事姓名。

自己的消息与同事消息使用不同方向和样式的气泡。具名头像、作者姓名和已识别的 @ 标签可以打开同一份同事详情。Markdown 内容继续使用 DSH 原语；提及高亮不得破坏代码块或把普通邮箱、无效名字当成可唤醒对象。输入框提供成员选择和明确的提及反馈，实际路由仍绑定同事身份，改名、重名和离职不会悄悄改变已确认的接收者。

群成员使用独立的身份与操作区域，姓名可以换行，状态徽标不挤出按钮；详情、私聊和移出等操作通过一致的按钮或菜单提供。窄屏通过成员入口展开列表，不要求用户穿过整个会话列表才能找到聊天输入框。消息失败、停止或仅完成工具调用时也要有可见状态，不能让一次 @ 没有任何持久化反馈。

## 3. 同事与岗位

同事页以具体的人为主体，显示姓名、岗位、任职及运行状态，支持搜索与筛选。选择同事后展示其当前固定的职责版本，并提供私聊、工作、记忆和任职管理入口。点击任何页面中的同事身份都应指向同一个人，跨页选择必须保持一致。

添加同事允许选择已有岗位模板，或在同一流程填写新岗位后创建具名同事，不要求先理解“定义”和“实例”。姓名修改是该同事的独立操作。职责和行为指令在明确标注的岗位编辑入口修改，不能把共享岗位修订伪装成个人资料修改；保存时继续询问是否同步既有同事，支持不更新、全部或选定同事。只修改姓名不会改变岗位、记忆、会话或权限。

岗位模板作为辅助管理入口保留。当前职责优先显示，历史默认折叠为版本列表，点击某一版本再看全文，不常驻重复铺开所有指令。任职状态不增加第三种状态；上下文重建、任务中断和运行错误作为运行信息展示。

## 4. 聊天创建工作卡

工作页不出现独立创建任务、创建草案或配置工作流的表单。它按同事展示已做、正在做和待确认的工作卡，默认提供工作摘要、负责人、可理解的执行状态、结果及来源入口。技术编号、授权与尝试记录放入详情。

同一个聊天输入框提供“消息”和“交办”两种明确操作。普通发送用于交流，不凭关键词或模型猜测生成执行授权。交办消息要求用户明确负责人；私聊可采用当前同事，群聊的多个 @ 或 @all 不自动决定负责人。正文就是完整工作指令，标题使用有来源的短摘要，用户不必重新填写另一套任务说明。

交办提交原子记录来源消息、任务、负责人和用户明确选择的委派权限，然后只投递一次正式任务，不额外派发一轮普通 @ 执行。同事安排其他同事的权限在交办前明确选择，默认关闭；发送普通消息、创建提议或使用模板都不会授予该权限。

智能体提出的新工作以来源聊天内的待确认卡展示，用户可以编辑、确认或拒绝。确认才开始新工作。同事在已经交办的范围内拆分自己的待办，作为该任务内的本人工作项记录，不扩大范围、改变负责人或重复启动任务；新范围仍提出待确认提议。给其他同事分配工作仍检查原任务的人类授权。

聊天来源是 Host、API 与工具共同执行的创建条件，不只是 Browser 隐藏表单。获得授权的同事委派也要在来源聊天持久化一条真实消息，再原子建立带来源的派生任务；工具或旧 API 不能绕过该条件创建无来源的新任务。人类确认提议和其他继续操作都记录自己的实际聊天来源。

模板仅用于把内容带入聊天；要求修改、结果交接及继续处理都保留相应聊天来源，创建的新工作也经过聊天确认。工作页的查看、停止、重试或结果导航不构成独立新任务入口。结果验收仍区分模型完成与人类接受，并定位到确切结果。

旧任务没有聊天来源时显示“历史任务，来源未记录”，不补造消息。继续处理旧任务时，由用户选择真实聊天，并为这次操作记录新的来源。卡片来源跨重启、切换组织和备份恢复保持可追溯。

## 5. 撤回与已读遗忘

### 使用效果

用户可以撤回自己发送的消息。聊天原位置保留撤回提示，不再显示原文；同事的有效记忆、检索、读取工具和后续会话不再自动提供撤回原文及已识别的依赖内容。只写一句“请忘记”或仅隐藏气泡都不满足验收。

已经包含该消息的同事会话必须结束并替换成全新会话。不能恢复、复制、压缩或总结被撤回内容所在的旧会话。未受影响的岗位、任职、群成员和允许保留的原始记忆继续有效。同事身份不变，用户无需重新招聘同事。

撤回前提示受影响的同事、可能被隔离的回复与结果，以及会中断的当前工作。工作记录保留实际状态，标明因上下文重建中断；不把中断伪装成完成，也不静默恢复含有撤回内容的执行。消息本身形成的交办不能通过旧任务重试重新输入；继续工作必须由人类重新提供允许使用的指令。

### 能承诺的范围

“遗忘完成”表示旧运行已结束，旧会话不得恢复，撤回内容和受影响来源已从本插件控制的后续模型输入中排除。测试检查实际组装的模型请求，而不是只检查聊天界面。

已经发生的文件修改、命令执行、网络请求和其他外部效果不会自动回滚。本功能不是提供商日志清除、备份销毁或对模型预训练知识的修改；同一信息被人类重新发送，或从独立外部文件重新获得，是新输入，不属于被撤回消息的继续记忆。原始持久化记录作为恢复和审计资料保留，但不得通过插件的模型记忆工具返回撤回原文。

插件旧日志、备份和受影响运行写出的内容副本不属于独立来源，不能拿它们自动重建上下文。本方案保证插件控制的会话、回忆、记忆查询和工作投递不重新使用失效来源；保留通用文件、终端和其他插件工具时，不承诺这些工具在任意读取旧副本的情况下也无法重新取得内容。禁止所有工具再次访问旧副本需要额外访问隔离或资料销毁，不在本轮默认范围内，不能用“遗忘完成”暗示资料已物理删除。

### 执行与失败

撤回持久化与禁止旧上下文准入及提交处于同一个组织操作屏障，不能在“先保存、后禁止”的间隙继续投递或提交旧结果。受影响同事的旧派发、插件工具写入、回复和子结果提交全部检查上下文代次，实际原子提交也重新检查，避免已完成但尚未落盘的旧输出穿过撤回。清理相关队列与 inbox，停止相关子运行，等待旧智能体释放完成，然后创建并绑定新会话。只有全部清理和替换完成才显示遗忘完成；不能承诺取消已发往外部系统的动作。

失败时显示“遗忘未完成”，保持受影响旧上下文不可继续使用，允许幂等重试。重启后先恢复未完成重建，不得以恢复旧 Session 的方式绕过撤回。不改变其他组织的任何同事、会话或任务。

新交付记录直接来源、实际回忆事件、累计会话输入来源和上下文代次。依赖隔离覆盖回复、任务结果、子结果，也覆盖工作草案、已确认指令、模板、成果摘要和交接上下文；投递、重试、草案确认与模板应用共享失效检查，不能通过另一个入口重新注入撤回内容。旧数据缺少可靠依赖关系时，采用保守方案：扩大到本组织全部同事的会话重建，并将撤回之后无法证明独立的运行生成内容和工作输入移出可用记忆与投递。该范围在撤回前显示，不能同时承诺精确遗忘与所有后续内容毫无影响。

## 6. 个人记忆

记忆页明确显示“某某的记忆”，并以同事名单选择记忆拥有者。从同事详情或聊天进入记忆时选中同一同事，不跳回排序第一人。

关键词搜索位于主内容顶部，类别与具名来源紧随其后。先展示对话、工作及子任务结果等用户可理解的类别，所有动作名称和来源类别都有中文与英文文案。私聊来源显示人名，子任务来源使用短标题，不能拿整段结果充当来源名称。

记录默认显示动作、来源和真实正文片段，展开再看 Markdown 全文、参与者及历史细节；序号、原始事件码、获得方式和版本定位进入高级筛选或详情。没有正文的记录描述实际动作，不生成虚构事实或无来源的知识摘要。筛选与搜索覆盖完整的有效个人记忆，不仅过滤已加载的一页；保留分页、去重和快照一致性检查。

## 7. 持久化与实现约束

继续通过现有 DSH 插件、Connection RPC 和存储域实现，不增加独立服务器，不修改 DSH 核心循环，不改变用户现有部署版本范围。群名、同事姓名、聊天来源、撤回、依赖关系和上下文代次由 Host 持久化，Browser 不自行决定权限或改写历史。

已提交的旧持久化格式、导出器与测试 fixture 保留。新增版本明确承载通信与上下文重建元数据，旧记录升级与旧导入提供未记录的来源和空新增事实，不伪造历史。新导出保存撤回、来源和重建状态，但仍不携带本地 DSH Session 内容或恢复旧会话绑定。导入不会自动执行任务。

模型可见的来源、权限、个人回忆和上下文代次必须记录到 Session 中。个人会话更换使用 DSH 支持的停止和新建接口；普通销毁后默认恢复旧绑定的现有行为不能充当遗忘实现。

## 8. 验收与交付

逐项覆盖用户反馈：群名保存和重启；气泡与提及；长姓名、运行徽标和窄屏成员操作；统一同事详情和跨页导航；撤回及已读上下文更换；以个人为主体且历史折叠的同事页；辅助岗位模板；聊天唯一创建工作入口及具名来源；中文、可搜索、可展开的个人记忆。

行为测试覆盖普通消息不新增执行授权、交办只投递一次、授权先于投递、本人待办不重复执行、待确认提议不执行、历史卡不伪造来源。遗忘测试覆盖未读、已读、正在执行、待提交、工具读取、子运行、转发、旧数据保守隔离、失败重试、重启和导入导出；实际后续模型输入不得含被撤回的唯一测试标记。

使用真实浏览器验证交互、键盘、中文、浅色与深色、桌面与窄屏，以及成员和全文阅读的实际可达性。完成构建、类型检查、相关行为测试及打包安装检查后，先备份本机资料，再安装本轮未发布构建并启动 DSH 给用户检查。该过程不代用户发送真实任务、不发布 npm、不 push 或打 tag。

## 9. 已核查的实现依据

- `packages/web/src/client/WorkspaceUi.tsx` 当前聊天只有普通发送，同事页面以岗位定义为主体；`WorkspaceTasks.tsx` 与 `WorkspaceWorkflow.tsx` 存在两套独立创建流程。
- `packages/host/src/workflow.ts` 支持同一更新内提交 aggregate 与 workflow；`workflow-tools.ts` 已有待人类确认的工作提议。
- `packages/host/src/memory.ts`、`memory-query.ts` 与 `memory-tools.ts` 目前直接读取原始事件，需要共享有效记忆选择规则。
- `packages/host/src/runtime.ts` 的单同事 generation 与 `dispose()` 可以拒绝旧排队操作并等待清理，但默认仍恢复已绑定 Session；需要明确的持久化重建流程。
- 已验证 DSH `0.2.0-rc.2` 的 `AgentHandle.dispose()` 停止、等待运行结束并释放作用域，`AgentRegistry.create()` 接受全新 Session；核查不等于本轮遗忘功能已实现或测试通过。
