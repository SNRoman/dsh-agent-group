# 公司工作流（第三阶段）设计

## 目的与范围

在第二阶段的独立组织中，提供可恢复的“草案→人类确认指派→执行结果→产物引用→人类审核→交接草案”闭环，以及可复用的任务模板和岗位/同事/群配置模板。用户已委托技术方案与实施；保留此前明确的人类指派、被 @ 才响应、平等模型/工具/技能权限、岗位修订、在职/离职和统一个人记忆规则。

不实现通用图形工作流引擎、自动接单、自动授权、跨组织自动协作、云服务、文件上传或产物真实性扫描；不 push、tag 或 publish。公司配置模板是在当前组织内建立配置，不自动创建另一个组织。

## 持久化

使用后继 `WorkspaceRecordV2 { recordVersion: 2, descriptor, aggregate, workflow }`。冻结 `WorkspaceState`、其 schema、已发布 fixtures 和 forward-v1 生产器；不向旧聚合添加字段或事件。`workflow` 有独立 revision、递增实体 ID、草案、模板修订、正式任务 brief、产物、审核、操作幂等记录和追加式事实。所有交叉引用必须属于同一组织的当前记录，并通过自身属性查找验证。

启动先验证整个目录，再把旧裸 local 或 recordVersion 1 升级为 recordVersion 2，补空 workflow，不虚构业务事实；升级只写一次。单个原子 record 更新同时保存聚合和 workflow，聚合更新不得覆盖 workflow。新增 portable formatVersion 3 包含 workflow；v1/v2 仍可导入，补空 workflow。v3 导入保留业务事实和内部身份、生成新组织 ID、重建投递 messageId，剥离 Session 和源组织创建元数据；实际提交的新本地组织记录本次导入的创建回执，以保证重复确认幂等，不启动模型。旧格式生产器继续原样可用，但明确不携带第三阶段元数据。

## 草案与正式任务

`TaskBrief` 包含简短 title、instructions、expectedArtifacts 字符串列表、acceptanceCriteria 字符串列表。草案记录来源（人类、可信员工提议、交接或需修改）、可选建议负责人、独立修订号及 draft/confirmed/discarded 状态。创建、编辑、丢弃和模板套用只写草案，不创建正式任务、不投递、不发 DelegationGrant。

人类确认必须明确选定仍在职的负责人，校验聚合、workflow 和草案修订；在同一次 table.update 内调用既有 `assignHumanTask`，保存完整 brief、唯一正式 TaskId 及确认事实。提交后才开始既有投递。重复同一 operationId 与相同命令返回既有结果，不再次指派或投递；改动命令复用 operationId 拒绝。确认提交后崩溃不会重复创建任务，恢复的未投递任务仍通过既有显式 retry 操作启动。

正式任务保留简短标题；任务投递根据已持久化 brief 确定性构造完整 instructions、交付物与验收内容，以及选中的交接产物。实际模型输入仍写入 DSH Session 的 user/message；后续模板或草案编辑不改变已确认 brief。普通旧任务仍使用既有投递文字。

员工仅获得 `workspace_propose_task` 工具，可在被明确唤醒的现有回合内提出草案；Host 从实际 Agent 对象确认组织和在职身份，不接受模型传入 actor/组织 ID。该工具不能确认任务、审核结果或授予权限。工具结果只返回草案 ID、摘要和“等待人类确认”，不返回整个组织。

## 模板

任务模板保存不可变 brief 修订；使用模板只生成一个可编辑草案，并记录使用的模板修订。修改模板生成新修订，不重写已有草案或任务。

公司配置模板保存不可变岗位修订 ID、待创建同事名称、可选群名称。人类先预览配置，再明确确认和选择“仅加入后新消息”的记忆起点；单个 record 更新创建新同事、固定其选定岗位修订、建立新群及成员关系。不得复制历史、Session、任务或授权，不唤醒员工。模板引用的岗位修订缺失、同事名称为空或模板内名称重复时拒绝提交；失败不留下半个配置。既有岗位定义继续作为岗位模板，不引入第二套岗位指令存储。

## 产物、审核与交接

产物由人类登记在本组织已有 `task/result` 或 `task/result-after-cancel` 的精确 eventId 和 attemptId 上，包含 label、summary 和可选文件路径/HTTP(S) 链接引用。页面明确引用未验证；不读取或执行本地文件，不自动访问链接，不把任意 URL 当成已经完成的文件上传。结果正文仍来自既有聚合。

人类审核绑定精确结果，记录 accepted 或 changes-requested 及意见。模型完成状态和人类审核接受是两件事；旧结果的接受不能自动覆盖后来结果。需修改只创建携带原 brief、结果与意见的新草案，仍等待明确负责人和人类确认，不重跑原任务。

交接选择已有结果和明确选中的产物，生成新草案，保存来源及选中引用的不可变内容。确认后按普通人类任务规则执行；不隐式转移权限或自动 @ 下一位员工。已取消任务的晚到结果可查看和登记，但界面明确其取消来源。

## 页面和通信

Tasks 内增加工作流区域，呈现草案编辑/确认、任务和公司模板、结果产物、审核与交接；保留原任务树及运行控制。所有操作绑定 immutable workspace API，RPC payload 显式 workspaceId。切换组织、关闭或卸载时取消旧刷新，旧结果不得覆盖当前组织；归档组织只读。所有产品文案属于 typed zh-CN/en-US locale。

workflow 快照与 aggregate 快照分别有 revision；写请求携带两者，命令解析拒绝用户伪造 actor。读写共享第二阶段 admission 和 teardown，不添加新的后台执行通道。持久操作的幂等身份同记录保存，取消在排队和原子提交前均检查，已提交业务不伪装成回滚。

## 验收

纯域与真实 storage 测试覆盖零投递草案、原子确认失败/重试、完整 brief 投递、模板修订固定、公司配置全有或全无、精确结果审核、交接选中引用、跨组织相同内部 ID、恶意关系引用、旧数据幂等升级和 v3 往返。工具测试证明真实 caller 可提议但不能确认/授权，离职或伪造对象拒绝。

DOM 验证每一条人类路径、归档只读、取消和跨组织迟到响应。packed DSH Browser 场景操作草案→确认→新结果→产物→需修改→确认返工→接受→交接，并演示模板预览/确认；重启与导入恢复后读取这些元数据。运行构建、Host/Client/type fixtures、文案检查、完整插件测试，并完成独立最终审核后本地提交第三阶段。
