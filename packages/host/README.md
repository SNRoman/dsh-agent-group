# @dsh-agent-group/host

Host-side support package for Agent Organization（智能体组织）, published as [`dsh-agent-group`](https://github.com/SNRoman/dsh-agent-group). It owns the durable organization domain, colleague runtime, dispatcher, memory/task policies, and live turn projection for DeepSeek Harness. Its service identifier remains `agentWorkspace`.

Most users should not install this package directly. Install the profile bundle instead:

```sh
dsh plugin --profile web add dsh-agent-group@0.5.0
```

Version `0.5.0` keeps the durable domain and aggregate at version `0`, with version-3 organization records for workflow and communication metadata. It reads released local aggregates and predecessor organization records, preserves formal Tasks, human grants, retryable delivery, cancellation, immutable definition revisions, unified Memory and ephemeral Runtime activity, and upgrades record wrappers at startup. Policy failures cross RPC as stable business-error codes and JSON-safe details; localized prose belongs to the Browser package.

Host membership commands require an explicit memory start: new events after the join, or an inclusive historical event range. The Browser's multi-colleague picker selects complete group history and future messages. Active silent members receive memory entries for room events even when they are not mentioned; mention routing alone decides which agents run.

Group names and colleague names can be changed through revision-checked commands without replacing identities, memberships, personal memory or role revisions. Direct-room labels remain derived from their colleague. A resident colleague's identity prompt is refreshed after its earlier work reaches idle, without replacing its Session.

Room replies and formal task deliveries use the colleague's unified personal history. Colleagues can search admitted events by keyword, receive references with sources and excerpts, and read original events on demand. Retrieval does not grant access to events absent from their personal memory, perform semantic/vector search, or enforce secrecy between rooms.

One-shot child runs use the registered DSH subagent provider named by the Host plugin's `childProvider` option. The default is `spawn`; deployments can select another installed provider in `cordis.yml`:

```yaml
plugins:
  dsh-agent-group/host:
    childProvider: spawn
    memoryCharacterBudget: 4000
    memorySearchResultLimit: 10
```

Configuration fails at the child-run boundary when the selected provider is not registered; the Host does not silently substitute another provider.

`memoryCharacterBudget` bounds the history layer and the source text returned by each memory tool call. `memorySearchResultLimit` bounds search previews. Both settings are positive integers validated when the plugin loads; response metadata is additional. `workspace_search_memory` returns acquired event IDs, source-labelled excerpts, and `hasMore`; `workspace_read_memory` returns original text, event sequence/type, first acquisition source, and a `nextOffset` for long text. Tools resolve the caller from its live employee handle, not from a supplied colleague ID.

### Scene memory

Every admitted employee turn receives its current organization, source room/task, actor, newly acquired original excerpts, applicable fact candidates, and relevant history. Original excerpts identify their actual source and sequence. Narrow applicable scopes and the current speaker take priority in the bounded core layer. The logged core labels current, organization-default, conditional, removed and unresolved candidates separately and retains source IDs; historical statements remain available through original retrieval and personal diagnostics. A newer original statement can supersede an older candidate while extraction is pending; facts do not grant work or delegation permission. `memorySceneCharacters` (2048), `memoryNewCharacters` (4000), `memoryCoreCharacters` (4000), `memoryItemCharacters` (1200), `memoryRecentConversationLimit` (12), `memoryFactLimit` (12), and `memoryHistoryLimit` (8) control the independent layers. The complete incoming user instruction remains in the ordinary delivery.

The logged scene includes the current delivery time in both UTC and the Host's local IANA time zone, including the offset at that instant. Local sessions interpret unqualified dates and times in this zone unless the user specifies another; a browser on another machine does not supply its zone through organization chat. Workspace event sequences remain the only known ordering of old sources, not invented source dates. The scene also records the persisted status of tasks assigned to the employee, including cancellation, without treating an old assignment message as permission to resume. The model-visible message counts original source excerpts separately from core fact references: a fact-only source is still reported as omitted original text. It also states partial excerpts and names `workspace_search_memory` and `workspace_read_memory` for follow-up. A missing `llm` service leaves extraction unavailable and its admitted attempt records a failed audit; it does not silently publish a fact. Read-only memory queries retain saved per-source processing status and report current extraction-model availability separately.

`memoryExtractionMode` defaults to `same-model-on-use`; `disabled` stops new auxiliary calls. After an employee model request has streamed, the Host extracts only personally acquired original fragments actually present in that request, using its selected provider/model. Startup, read-only memory queries and silent messages do not export dormant history. Auxiliary calls have no tools, visible Session, or custom Session events. Each exact source fragment is shared across colleagues; source eligibility is checked again for every personal read. The v2 extraction protocol has server-owned `person.address` and `communication.language` slots, plus original-text-anchored stable preferences/standing agreements and non-core context. `sourceLocation` in its prompt names where an event was recorded; separately quoted application evidence determines organization, source-room, source-task or unresolved applicability. A room source is not automatically room-limited. Recorded actor identity, exact source quotations, operation (set/remove/clear), temporal status and source sequence govern projection. Unknown aliases, elided topics, unsupported ranges and incomplete sources remain unresolved rather than gaining invented current values; model semantic classification is not guaranteed by substring validation.

Extraction requests and raw terminal streams are retained in the native `agent_workspace_memory_audit` domain (version 3, `requests` table), which reads retained domain versions 1 and 2 without changing their records. The independent `agent_workspace_memory_projection` domain (version 2, `fragments` table) is a disposable cache reconstructed from successful audit settlements and also reads retained v1 records. V1 free-key facts cannot enter v2 current core or count as v2 completion. Only a later on-use exposure can create a v2 extraction, and a missing v2 projection reuses only a completed v2 audit. V2 audit failures optionally record `failureKind`: only explicit `validation` rejection skips another attempt for the same exact source and extraction protocol; `retryable` provider/processing errors and older unclassified failures remain eligible on a later exposure. Rejected sources remain failed diagnostics but do not consume later requests' bounded source allowance. The request is durable before dispatch, and its settlement is durable before facts become available. Restored or late results cannot make a withdrawn source eligible. These domains do not change released Workspace records or portable exports. Audit records contain the exact exposed text and model output and remain local audit data after withdrawal.

Organization stop permanently cancels the admitted extraction generation and waits for its durable settlements before reopening. A projection still being written remains unreadable; cancellation durably marks its audit `discarded`, so restored readers reject the late projection. Previously completed facts remain available. Failure to persist a discard rejects stop and reopening and keeps the affected audit unreadable in the live runtime; forced restart after that storage failure does not establish durable cancellation.

The Host opens memory domains with their current schemas. For a backend that rejects a declared predecessor unit header, it retries only the explicitly compatible versions on `StorageError` code `version-mismatch`; schema, malformed-medium and other failures remain fatal. Opening does not rewrite original audit bytes. A fallback domain handle retains that predecessor unit version on later writes; this is read compatibility, not downgrade support for older plugin schemas. Disposable per-record projections retain the backend's native accepted-version and foreign-record handling.

`memoryExtractionCharacters` (1600), `memoryExtractionSourcesPerRequest` (8), `memoryExtractionMaxPending` (16), `memoryExtractionMaxTokens` (2048), and `memoryExtractionTimeoutMs` (30000) bound auxiliary work. The timeout applies independently to metadata resolution and the subsequent extraction stream. `memoryExtractionReasoningEffort` defaults to `auto`: the Host selects `off` only when the exact employee provider/model advertises it, otherwise leaves the adapter/provider default in force and records a known metadata default in the audit. Explicit nonempty values must match an advertised effort ID; an unsupported value or metadata error produces a failed audit before model dispatch. The selected auxiliary parameters are durable before extraction and do not change the employee request's effort. Fragments are processed serially per organization; cancellation fences publication and aborts the call. Each candidate is validated independently: valid facts remain available when a sibling fails validation, while the audit preserves the rejection reason and source progress remains failed. A candidate rejected by schema or source-evidence validation is not re-dispatched for the same source and extraction version; changed source text or a new protocol version can be processed. A processed prefix is `partial`, including when it yielded no facts. Unseen sources are `unprocessed`; original source synchronization continues when extraction fails. Later employee requests can expose and process remaining ranges. `WorkspaceRuntime.memoryProcessingStatus(agentId)` returns personally filtered sources, ranges, candidate facts, mode, availability and the `local-lexical` retrieval channel; `waitForMemoryProcessing()` waits for currently admitted auxiliary work and durable settlements.

Automatic history and `workspace_search_memory` share MiniSearch 7.2.0 with Chinese bigrams and word tokens. Only acquired, valid sources are indexed before ranking and result caps. An event acquired through several legacy entries is indexed once; the original entries retain their first-source provenance and individual receipt coverage. The scene's current colleague directory includes the saved definition role alongside each name. `memoryContextCharacters` (800; zero disables) bounds nearby source text used with the actual query to rank ambiguous questions. This is local lexical retrieval, not embedding search; no embedding key, provider or cloud destination is added. Source excerpts remain the authority. The synthetic benchmark at `output/memory-evaluation/20261014/scene-benchmark.ts` compares lexical and layered selection with hand-authored candidate fixtures, not model answer quality.

The package exports `createForwardWorkspaceExportV1` and the frozen format constants from `@dsh-agent-group/host/forward-export`. The helper validates and clones a legacy local aggregate, omits workspace-local session bindings, and returns an RFC 8785 canonical document with a SHA-256 digest. The repository command `pnpm export:forward-v1` is a read-only file adapter. Use the Browser's format-4 export for current organizations with workflow and communication metadata.

## Organization recovery

Chat assignment atomically stores a real human message, complete work brief and source identifiers before delivery. Employee proposal and delegation tools require a real room and resolve the caller from its running Agent, not model-supplied identity. Source-free legacy Browser task creation is refused. Workflow reads exclude withdrawn references; durable audit records remain unchanged, and atomic write checks also reject stale retry receipts for invalidated work.

Message withdrawal fences organization admission before persistence, stops and drains old work, blocks late outputs, and creates unseeded replacement Sessions. Failure remains durable and blocked across restart or import. Input attribution distinguishes incoming room messages from generated output, records context generation and source dependencies, and reaches the Session log with the managed model input.

Removing a group member retains personal memory by default. The optional `room/leave-and-forget` RPC atomically ends that membership, removes only that colleague's group acquisitions and personally generated room replies with recorded dependencies on them, and fences its old Session generation. Shared room messages, other colleagues' memory, and independently authorized task/child-result acquisitions remain stored. Source-derived facts require personal acquisition on every read, including late extraction results. The Host temporarily blocks new organization operations while admitted work drains; it stops only the affected colleague's deliveries and children, lets other colleagues finish, and binds an unseeded Session before reporting completion. A durable failed reset stays blocked and can be retried with its original operation ID, including after restart. Original Session files and local audit data are not physically erased. Rejoining with history synchronization creates new personal acquisitions from the preserved room history. The explicit `room-memory-forget` variant belongs to the version-3 communication metadata; released aggregate and predecessor export schemas remain unchanged.

A recovered pending task matches its saved delivery message and attempt to one managed input, refreshes its recall before the model request, logs that receipt, and attributes later memory-tool reads to the same input; inconsistent or ambiguous saved attribution is rejected. Organization stop invalidates recovery already in preparation, discards its exact pending inbox message even before the resumed employee is published, and drains the resulting task settlement. Reopening permits a new recovery generation but never revalidates an old claim. Optional delivery identifiers belong to the version-3 communication metadata: older inputs without them still load, while recovery can create a managed input when an older pending task has none.

Local file recovery is separately opted in; private raw-byte checkpoints support existing regular files only, with per-file conflicts and independent retries. Limits and storage directory are configurable through `fileCheckpointDirectory`, `fileCheckpointMaxFileBytes`, `fileCheckpointMaxFiles` and `fileCheckpointMaxTotalBytes`; exports omit file bytes and local Session bindings.

File recovery and preview are scoped to the inputs first invalidated by the selected withdrawal. Consent for a later withdrawal does not include files from an earlier opted-out withdrawal; retrying an earlier withdrawal does not include later work. Trusted UTF-8 checkpoint content is available to the human preview as before/after text, within the journal's configured byte limits. Binary or unavailable blobs have no text preview; preview text is not persisted or exported. Recovery excludes links, provider paths, conflicting writes, new-file deletion and missing-file recreation. It cannot undo arbitrary shell/network effects or atomically prevent another process from writing the open file.

The `@dsh-agent-group/host/workspace-import` leaf provides `prepareWorkspaceImportV1(json, options)`. It validates an existing forward-v1 document and returns a detached candidate for a caller-assigned new organization ID. It does not write storage, create an organization, register a service, restore model sessions, or run work.

The caller supplies positive safe-integer limits for UTF-8 document bytes (`maxBytes`), aggregate records including memory entries (`maxEntities`), events (`maxEvents`), each string/key's UTF-8 bytes (`maxStringBytes`), and JSON container depth (`maxDepth`). The decoder verifies the SHA-256 digest of the original parsed envelope, strict version-1 fields, and all aggregate relationships. It rejects `__proto__` fields before schema conversion, and rejects duplicate object fields and invalid Unicode as required by [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785), while accepting whitespace and arbitrary field ordering. A digest detects corruption; it does not establish authorship. Exports contain potentially sensitive role instructions and complete organization history, so callers must obtain human confirmation before later committing a candidate.

Candidates retain entity/event IDs, event order, employment periods, definitions, grants, tasks, and personal memory. They discard old Session bindings and rebase task-delivery message IDs and their attributed task-input references to the new organization ID without changing the source document. Source and target relationships are validated separately; room-input identities, unattributed legacy inputs and message text remain unchanged. Pending task deliveries and running children are rejected rather than resumed or silently repaired. Source plugin versions and declared import ranges remain diagnostic information, not an acceptance policy.

The service exposes a durable directory and `ctx.agentWorkspace.forWorkspace(id)` for fixed organization runtimes. The strict version-`0` domain reader accepts released local aggregates and version-`1`/`2`/`3` organization records. Startup validates all records before upgrading predecessor records to v3 once, adding empty missing workflow and communication metadata without fabricating facts; events, memory, entity IDs and local Session bindings remain unchanged. Each organization has its own runtime, pool, activity stream and child controls. Creation/import retries reuse a durable operation identity; reusing it with different input fails instead of creating another copy.

Windows atomic-rename contention retries are limited by `storageWriteRetries` (default 5) and `storageWriteRetryDelayMs` (default 50). Only unpublished `EPERM`/`EACCES` rename failures are retried; other storage failures remain errors, and mutations stay serialized without duplicate business events.

`@dsh-agent-group/host/workspace-portable` exposes `createWorkspaceExportV4` and `prepareWorkspaceImportV4` for communication-aware exports and the shared v1/v2/v3/v4 reader. Frozen v1/v2/v3 producers and their readers retain their formats and reject successor records; `prepareWorkspaceImport` remains the v1/v2/v3 reader. The live service enforces idle export, read-only previews and create-new import. It rejects unfinished durable work, removes aggregate Session bindings and communication context Session proofs, and never runs imported tasks automatically. Archive closes admission before persisting its lifecycle; stop mode cancels exact organization-owned work, while wait mode drains already admitted work. Both wait through settlement, Session persistence and child disposal. An archive write failure restores admission without stopping work. Reopen requires quiescence.

`WorkspaceRecordV3` stores the complete raw aggregate and workflow beside communication sources, input dependencies, withdrawals, context generations, reset operations and checkpoint metadata. Directory reads and atomic replacements validate both structure and communication references. Aggregate and descriptor writes preserve all communication metadata. Effective model-input projections contain event sequence gaps and must never replace the raw stored aggregate. Portable format 4 preserves withdrawals and pending/failed resets, omits local Session proofs, and marks checkpoints unavailable because backup JSON contains no file bytes. Byte hashes, sizes and normalized relative paths remain; local blob references are replaced with unavailable markers. Format 4 requires the `0.5.x` reader; older plugin versions cannot read it. These data readers do not implement context stopping, Session replacement or file restoration.

The following validated positive safe-integer settings own import budgets. Defaults keep JSON-wrapped requests within the Browser adapter's default one-MiB body limit:

```yaml
plugins:
  dsh-agent-group/host:
    importMaxBytes: 262144
    importMaxEntities: 50000
    importMaxEvents: 20000
    importMaxStringBytes: 131072
    importMaxDepth: 64
```

Larger backups require increasing `importMaxBytes` and, when appropriate, the other budgets. Also increase `maxRequestBodyBytes` on the installed `@dsh-agent-group/host/web-rpc` adapter enough to accommodate the file encoded inside the RPC JSON envelope. Import errors omit source text. A checksum is not an authentication mechanism. Backups retain raw withdrawn organization history, but omit extraction audit/projection domains, local Sessions and file bytes. Keep exports private. Package downgrade does not reverse record upgrades; retain a complete stopped-profile backup from before upgrading for rollback.

Host unloading rejects new directory and runtime work, stops admitted execution, and waits for outstanding directory writes, task settlement, child disposal and employee Session cleanup before closing the domain. Cleanup attempts every organization even if one fails; Cordis reports rejected teardown effects through its logger rather than rejecting `fiber.dispose()`.

## Company workflow

The workflow fields shared by `WorkspaceRecordV2` and current `WorkspaceRecordV3` own drafts, immutable task/company template revisions, confirmed task briefs, exact-result artifacts and reviews, handoff snapshots, operation receipts and ordered facts. They are validated and saved atomically with the aggregate and current communication metadata. Aggregate-only writes preserve workflow metadata. Human writes carry both revisions; durable operation replay is checked before CAS and returns the same receipt without repeating task assignment or delivery. Changing the semantic command under the same operation ID fails.

The type-only `@dsh-agent-group/host/workflow-contract` leaf is safe for Browser type imports. Model-visible full briefs are rendered from confirmed persisted metadata and logged in the existing DSH Session user input; legacy tasks keep title-only delivery. An available coordinator starts delivery only after commit. A committed but undelivered task after a crash or runtime absence remains explicitly retryable; operation replay and later runtime availability do not start it.

Only the trusted actual employee Agent can call `workspace_propose_task`, and the atomic write rechecks employment. Proposals create drafts and return bounded identifiers and a waiting-for-human status, never tasks or delegation grants. Template preview/application does not wake employees. Company configuration confirmation creates new colleagues pinned to selected role revisions, groups and explicit new-events memberships atomically, without copying historical work or Sessions.

Artifacts and human reviews identify an exact task result event and delivery attempt. Path and HTTP(S) references are inert and unverified. Changes-requested and handoff operations copy result context into a draft; handoffs copy only explicitly selected artifacts. They neither execute work nor transfer authority. Workflow operations share organization admission, archive read-only enforcement, cancellation and root teardown with existing work.
